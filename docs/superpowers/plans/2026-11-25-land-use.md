# Land use: a believable island from the drone — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Land use (fields, pasture, orchards, vineyards, scrub, dunes, fallow) covers the whole island by region, coast, slope and villages instead of lining the roads; far away it is paint in the ground, near the camera it is planted; the menu drone gets thick haze and no visible ground edge.

**Architecture:** A pure, seeded parcel planner in `world/plan/landUse.js` (worker) replaces `planFields`; arable parcels become today's `Field`s, so crops, stalks, farms and fauna keep their inputs. The worker paints the parcels into one RGBA land-use texture that the terrain shader blends over the vertex colour. Step B adds planting by distance (merged field meshes per chunk, instanced orchard/vine rows, walls/hedges, scrub) with reaches per quality level.

**Tech Stack:** plain ES modules, vendored Three.js, node test runner, Playwright (shots only).

**Spec:** `docs/superpowers/specs/2026-11-25-land-use-design.md` (under `docs/superpowers/specs/2026-11-23-three-js-world-design.md`).

## Global Constraints

- Layering per `client/layering.mjs`: plan and paint in `world/` (pure, worker, no Three.js); drawing in `view3d/assets/` and `view3d/scene/`. New world fields reach the page only if listed in `sceneOf` (`view3d/worldScene.js`), and transfer as typed arrays.
- Deterministic by world seed (`seededRandom`, `fbm` from `world/noise.js`); no `Math.random`.
- Budgets (spec): ride draw calls vs `~/.cache/openradlr/screenshots/move3/after.txt` (low 451, medium 811, high 1282, ultra 1612): Low/Medium ≤ +10 %, High/Ultra ≤ +15 %; the menu's draw calls and triangles ≤ +10 % over the Task 0 baseline. Paint texture ≤ 2048 × 2048 texels; parcel data a few MB at most.
- Regions (#127) stay; their `fieldShare` and `crops` stay the base of the mix. Roads, rivers, towns, landmarks and farmstead buildings are not changed.
- Commits: Conventional Commits, imperative, user-facing, trailer exactly `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`; no model ids.
- Gate per task (repo root): `docker run --rm -v "$PWD":/w -w /w/client node:22 sh -c "npm run lint && echo LINT OK && node --test 'test/**/*.test.js'"` — LINT OK, 0 failures. `npm run preload` when a page's import graph changes. No temp files in `client/`.
- Designer's call changed from the spec: woods keep running **after** the parcels (as they run after fields today) and fill the land no parcel took; "wild" land (no parcel) is theirs. The menu budget is measured in draw calls and triangles, not frame time (software GL timing is noise).

## Review Focus

1. **A map with no regions or no villages** (`regions: []`, `settlements: []`, e.g. tracks and the test fixtures): the planner still returns parcels from the default mix and never throws. Test in Task 2.
2. **Huge islands** (`ground.huge`): the paint stays ≤ 2048 texels a side and the planner stays under its time budget (a 30 × 30 km bounds test finishes in < 5 s in node). Tests in Tasks 2 and 4.
3. **Winter and autumn** (season changes rebuild the world): each kind paints a season colour; nothing falls back to black or summer green in winter. Test in Task 4.
4. **Fields under a farm yard, café or town** (`MASK.built` before the parcels): no parcel overlaps built ground, a road or a river. Test in Task 2.
5. **Quality changes mid-ride** (`setQuality`): the step-B layers rebuild with the new reaches and nothing leaks. Test in Task 7.

### Task 1: Land kinds and their mix

**Files:**
- Create: `client/public/js/world/landKinds.js`
- Test: `client/test/landKinds.test.js`

**Interfaces:**
- Produces:
  - `LAND_KINDS = ["arable", "pasture", "orchard", "vineyard", "scrub", "dune", "fallow"]`.
  - `LAND_STYLE[kind] = {paint: {spring, summer, autumn, winter}: [r, g, b] sRGB 0–1, edge: "wall"|"hedge"|"none", size: [min, max] metres}`; arable's paint is ignored (its crop decides, see Task 4).
  - `CROP_PAINT[cropId] = [r, g, b]` sRGB 0–1: the ground colour of every crop id that appears in any `REGION_STYLE[*].crops[season]` (match the colours `assets/nature/crops.js` draws, by eye).
  - `COAST_BAND = 220` (metres from the shore: no arable, orchard or vineyard), `PLOUGH_SLOPE = 0.12` (steeper: no arable), `TERRACE_SLOPE = 0.3` (steeper: no parcel at all).
  - `landKindWeights({mix, shore, slope, height, village}) -> Record<kind | "wild", number>` (sum 1): `mix` = `regionMix` output, `shore` metres to the sea, `slope` rise/run, `height` above water, `village` metres to the nearest settlement or farm anchor. Base from the regions: arable ∝ `fieldShare`; Mediterranean kinds (`pineCoast`, `oliveTerraces`, `almondValley`, `lavenderFields`) favour orchard/vineyard/scrub, green ones (`meadow`, `farmBelt`, `wetland`) arable/pasture, `deepWood`/`highCountry` wild/pasture/scrub. Farmland weight falls with `village` (half at 1500 m); `wild` takes the rest. Edge default by region family: Mediterranean → wall, green → hedge.
- [ ] **Step 1: failing tests** (`landKinds.test.js`)
  - `weights sum to one for every region kind` — each kind alone, flat ground, shore 2000, village 300: sum 1 ± 1e-9, all ≥ 0.
  - `no ploughland or orchards in the coastal band` — shore 100: arable, orchard, vineyard weights 0; scrub + dune > 0.5.
  - `steep ground is not ploughed` — slope 0.2: arable 0; slope 0.35: every parcel kind 0 (wild 1).
  - `farmland clusters near villages` — farmBelt: arable at village 200 > 2 × arable at village 3000.
  - `regions differ` — the argmax kind of `oliveTerraces` is orchard, of `farmBelt` arable, of `highCountry` wild or pasture.
  - `every crop has a ground colour` — every crop id in every region's `crops` of every season has a `CROP_PAINT` entry.
  - `every kind paints all four seasons` — each `LAND_STYLE[k].paint.<season>` is 3 numbers in [0, 1].

### Task 2: The parcel planner

**Files:**
- Create: `client/public/js/world/plan/landUse.js`
- Test: `client/test/landUse.test.js`

**Interfaces:**
- Consumes: Task 1; `MASK`, `maskAt`, `stampField` (`world/plan/masks.js`); `regionMix`; `seededRandom`, `fbm`.
- Produces:
  - `Parcel = {kind, x, z, width, depth, yaw, corners: Float32Array(12) (x, y, z of −w−d, +w−d, +w+d, −w+d at terrain height), crop: string|null (arable only: a crop id of the region's `crops[season]`, as `planFields` picks today), edge: "wall"|"hedge"|"none", tint: number (−1…1, per-parcel shade)}`.
  - `planLandUse({terrain, roads, regions, settlements, seed, season, masks, water, bounds}) -> {parcels: Parcel[]}`; stamps every parcel with `stampField` (so woods, roadside and fauna keep off it as off fields today).
  - Algorithm (the part tests don't fix): walk the land in blocks of ~400 m; per block pick a grain angle (the nearest road's tangent within 600 m, else `fbm` noise), split the block along the grain into strips and the strips into parcels of `LAND_STYLE[kind].size`, each jittered by up to 15 %; draw each parcel's kind from `landKindWeights` at its centre (`shore` from the terrain: distance to the nearest point below `water`, from a coarse 50 m distance field computed once); drop the parcel if any corner or the centre hits a non-free mask cell, lies below `water + 1`, or the kind is `wild`.
- [ ] **Step 1: failing tests** (`landUse.test.js`, on the browser's world inputs as `world3.test.js` builds them, plus a tiny synthetic terrain for the edge cases)
  - `parcels lie away from the roads too` — valley map: ≥ 40 % of arable parcels have their centre > 300 m from every road.
  - `the coast is not ploughed` — no arable/orchard/vineyard parcel centre within `COAST_BAND` of the shore.
  - `no parcel on a road, river, built ground or the sea` — every corner and centre: mask free before stamping (check by replanning on a fresh mask copy) and height ≥ water + 1.
  - `the same seed plans the same land` — two runs deep-equal; another seed differs.
  - `a bare map still gets land use` — `regions: []`, `settlements: []`: > 0 parcels, no throw.
  - `a huge island plans in time` — synthetic 30 × 30 km flat island: finishes < 5000 ms.
- [ ] **Step 2:** Run → FAIL. **Step 3:** Implement. **Step 4:** Gate → PASS.
- [ ] **Step 5:** Commit `feat(client): Plan fields, pasture, orchards and scrub over the whole island`.
