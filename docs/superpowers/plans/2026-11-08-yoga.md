# Yoga Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Three yoga classes at the Beach Café gym (seven new poses), with a translated cue line per exercise and a left/right side switch that every rider sees.

**Architecture:** Poses are ordinary exercise ids end to end (server enum, client registry, clips, statues). A sided pose is one block: the client sends `side: "right"` at its start and `side: "left"` at its midpoint; the server keeps `side` in `RiderTags` and broadcasts it in `riders[]`; the view mirrors any rider whose side is left.

**Tech Stack:** Rust (serde) server; plain ES-module client, `node --test`; own WebGL renderer.

**Spec:** `docs/superpowers/specs/2026-11-08-yoga-design.md`

## Global Constraints

- New exercise ids, exactly: `sun_salutation`, `forward_fold`, `downward_dog`, `cobra`, `child_pose`, `low_lunge`, `pigeon`. Sided: `low_lunge`, `pigeon` only.
- Side values on the wire: `"right"`, `"left"`. Error code for a bad one: `unknown_side`.
- No `PROTOCOL_VERSION` bump (stays 2); `docs/protocol.md` notes the additions under the version-2 additions line.
- All UI text through `t()` with literal keys in `en.js` and `de.js` (ADR 0017; the key sweep test reads literal keys).
- Commands run in Docker (no host node or cargo):
  - client: `docker run --rm -v "$PWD":/w -w /w/client node:22-alpine node --test "test/**/*.test.js"`
  - lint: `docker run --rm -v "$PWD":/w -w /w/client node:22-alpine sh -c "npm ci --silent && npm run lint"` (npm, `package-lock.json`)
  - server: `docker run --rm -v "$PWD":/w -v cargo-cache:/usr/local/cargo/registry -w /w/server rust:1 sh -c "rustup component add rustfmt clippy >/dev/null 2>&1; cargo test --workspace && cargo fmt --check && cargo clippy --workspace -- -D warnings"`
- Commit messages imperative, ending with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`.

## Review Focus

1. **Keepalive resets the side.** `workout/keepalive.js` re-sends the current exercise every 30 s; if it sends no side, the server falls back to right mid-hold. Test in Task 3.
2. **Pause or skip in a sided block.** Pause sends rest (`null`, no side); resume after the midpoint must send `side: "left"` again, not right. Test in Task 3.
3. **A side change restarting the clip.** Only the exercise may reset `exerciseSince`; a side change must keep the clip time. Test in Task 4.
4. **The penguin rig.** `client/test/penguinWorkout.test.js` runs every clip on the winter penguin; new clips must pass it as well as `clips.test.js`. Covered by Task 2's suite run.
5. **A side on rest or on a non-sided exercise.** The server drops it, so a stale `left` never shows on the next pose. Test in Task 1.
